# 07 合成数据：生成训练信号，保留独立评价

对应公开课程地图 W7：Synthetic Data & Governance。
合成数据是模型、程序或模拟环境产生的训练记录。它可以有价值，但每条记录的来源与验证方式必须可追溯。
“生成了训练解答”和“捏造了实验得分”是性质完全不同的两件事；本教材只允许前者。

## 7.1 三个场景揭示不同的学习信号

**场景一：数学题有答案，缺少可读解法。** 在公开训练题上，让教师模型生成多条解法，用可靠判分器筛选最终答案正确的候选。
筛选后的解法可以用于 SFT，但最终答案正确不证明每个推理步骤正确。
模型也可能碰巧猜对，或者在错误过程后写出已知答案。

**场景二：分类任务只有短指令。** 从人工种子任务生成不同表达、输入和标签。
多样化可能扩大覆盖，也可能只是重复模板。几万条高度相似任务并不等于几万种技能。
若教师为自己打分，质量上升可能只是其风格偏好变强。

**场景三：代码解答需要执行。** 对公开训练任务生成代码，在隔离环境执行可信测试。
通过训练侧测试的代码可以成为示范；隐藏测试仍需独立评价。
让模型同时生成代码与测试，可能形成“错误代码被弱测试认可”的闭环。

选择流程前，先写明缺的是 instruction、response、preference 还是 environment trajectory。
不要因为生成文本便宜，就把所有任务改造成“让教师写更多长答案”。

## 7.2 教师分布、筛选分布与学生分布

设真实训练任务为 $x\sim q(x)$，教师为 $p_T(y\mid x)$，接受规则为 $a(x,y)\in\{0,1\}$。
接受后的条件分布是：

$$
q_{\mathrm{accepted}}(y\mid x)
=\frac{p_T(y\mid x)a(x,y)}
       {\sum_{y'}p_T(y'\mid x)a(x,y')}.
$$

分母是这个题目的接受概率，可能很小，也可能为零。
若每道题生成固定 $K$ 条，再把所有通过样本合并，容易题会贡献更多训练样本。
若每题固定保留一条，题目权重更均衡，却可能丢弃多样解法。
因此必须同时记录每题生成数、接受数和最终采样权重。

学生 SFT 通过最大似然拟合这个接受分布。
它学习的是教师与筛选器共同定义的行为，并非直接学习“真理分布”。
若筛选器只奖励正确数字，接受分布仍可能包含格式混乱或推理错误。

## 7.3 四种常见生成方式

| 方式 | 输入 | 新产生的记录 | 主要风险 |
| --- | --- | --- | --- |
| 指令扩展 | 人工种子任务 | instruction/input/output | 模板重复、标签错误、覆盖偏斜 |
| 蒸馏 | 真实训练题、教师模型 | 教师回答或概率 | 继承错误、许可条件、风格过拟合 |
| 拒绝采样 | 每题多个回答、验证器 | 通过筛选的回答 | 简单题过采样、验证器盲点 |
| 偏好生成 | 同 prompt 多候选、判断规则 | chosen/rejected | 假偏好、长度和措辞捷径 |

[Self-Instruct](https://arxiv.org/abs/2212.10560) 提供了生成指令、输入、输出并过滤无效与相似样本的研究范式。
本章借其方法分类解释概念，不复用其文本，不把其论文提升幅度移植到本项目。
若论文使用专门策划的新评测，本作业也不据此另造 benchmark；这里使用既有公开任务。

## 7.4 从训练 split 生成，而不是改写测试答案

使用 [MATH 官方项目](https://github.com/hendrycks/math) 或 [GSM8K 官方项目](https://github.com/openai/grade-school-math) 的训练 split。
在训练 split 内预先划分 `train_generate` 与 `dev_select`，保持题目 ID 和内容摘要。
教师只能看到 `train_generate` 的题目；需要答案验证时，判分器读取训练答案。
公开 test 的题目、标准解答和评测输出都不进入生成提示、筛选阈值调优或学生训练。

GSM8K 的官方记录包含 `question`、`answer`，答案末尾使用 `####` 标出最终数值。
源记录中的计算注释是否保留，是一项可复现预处理决策。
MATH 的数学等价判断比数字字符串匹配复杂，应使用可信评测实现并固定版本。
不能临时把“包含答案子串”写成验证器；答案 `2` 会被许多错误回答碰巧包含。

测试污染还可以来自教师的未知训练资料。
采用公开模型并不能证明教师没见过 benchmark，因此记录教师模型 ID、revision 与已知训练信息。
把它作为实验限制，不能声称“完全零污染”。

## 7.5 生成日志应该保存什么

每次采样记录完整提示的摘要、模板版本、教师 revision、temperature、top-p、最大输出长度、随机种子与采样序号。
记录停止原因：正常 EOS、长度截断、工具错误或请求失败。
失败请求不能悄悄从成本分母中删除，截断回答不能默认为完整示范。

以下是字段规范示意，不是训练数据或实验结果：

```json
{
  "source_dataset": "public_dataset_id",
  "source_revision": "pinned_revision",
  "source_split": "train",
  "problem_id": "source_id",
  "teacher_revision": "pinned_model_revision",
  "prompt_template": "math_completion_v1",
  "sample_index": 0,
  "completion": "stored generated text",
  "stop_reason": "eos",
  "verifier_version": "pinned_verifier_revision",
  "verifier_result": "record actual verdict",
  "accepted": false
}
```

不要将模板占位符作为真实样本提交；报告中给出实际 manifest 和生成日志的路径。
对私有教师服务，应保存服务版本可得信息及调用日期，不能用一个通用模型名代替所有版本。
API 费用、教师推理 token 和学生训练 token 是不同成本项，分别统计。

## 7.6 验证器的能力边界

验证器可以分为格式、最终答案、执行测试、形式化证明等层次。
格式通过只说明回答可以被解析；执行通过也只说明给定测试未发现错误。
奖励必须与这些证据层次对应，例如称为“公开测试通过率”，而不是“程序永远正确”。

对训练侧正确性验证，应使用冻结代码并保留错误案例。
若判分器异常，区分 `invalid` 与正常错误 `incorrect`。
把所有异常都记为零可能把环境故障学习成任务难度；把异常丢弃又会抬高报告中的通过率。
应同时报告有效判分率和条件正确率。

如果让教师重写自己失败的答案，保存各轮 ancestry。
否则最后一条通过样本看起来像独立生成，隐藏了反复试错成本和答案提示。
当修复提示包含标准答案时，应称为“答案条件蒸馏”，不能称为独立解题采样。

## 7.7 数量、多样性与错误率如何相互作用

如果单条候选独立正确概率为 $p$，每题采样 $K$ 次至少一次正确的概率是：

$$P(\text{至少一次成功})=1-(1-p)^K.$$

这是一种理想化模型，实际候选通常相关。
例如重复同一个解题模板，增加 $K$ 的边际收益可能很小；改变采样温度又可能提高格式失败率。
比较生成策略应记录每题成功率与单位推理成本，不只统计通过样本总数。

多样性不等于温度越高越好。
可以观察题目类别、答案长度、词汇覆盖、近重复率、不同解法结构，以及分难度接受率。
这些是训练数据诊断，不替代公开 benchmark 的模型评价。
从 teacher 输出中发现低质量簇，应修改生成与筛选规则，而不是只删除看起来不漂亮的个例。

## 7.8 合成占比与退化

混合真实示范和合成示范，可定义 $q_\alpha=(1-\alpha)q_{\mathrm{real}}+\alpha q_{\mathrm{synthetic}}$。
$\alpha$ 要说明按 token、记录数还是 prompt 数计算。
一条很长的合成推理链可能令合成 token 占比远大于合成记录占比。

递归使用学生输出训练下一代学生，会改变尾部分布与错误结构。
不能把“用合成数据必然崩溃”或“无限合成必然提升”当成无条件定律。
保留真实锚点、独立评价和失败追踪，是能直接执行的控制措施。
每代更新还需重新审计 benchmark 重叠与 teacher/student 的共同错误。

## 7.9 与本仓库实现的连接

[`data.py`](../src/fm_tutorial/data.py) 的 `prepare_jsonl` 可对文本做规范化和精确去重，但不是 instruction 数据处理器。
合成记录的 prompt、completion、teacher、verifier 字段必须由对齐数据整理层保留。
不能先拼接所有字段交给预训练数据工具，再期待它自动生成 response mask。

[`alignment.py`](../src/fm_tutorial/alignment.py) 接受已经 tokenized 的 logits、ID 与 completion mask。
mask 标记哪些目标 token 属于学生应学习的回答；第 08 章详细推导位移规则。
本模块不调用教师、不下载数据、不保证生成记录质量。
数学诊断脚本通过，只表示损失接口正确，不表示合成数据改善了模型。

## 7.10 一个可审计的真实实验

在 MATH 官方训练题上固定教师、生成预算与答案验证器，构造以下条件。

| 条件 | 训练信号 | 要隔离的因素 |
| --- | --- | --- |
| A | 原始训练解答 | 基础示范质量 |
| B | 未筛选教师解答 | 生成带来的分布改变 |
| C | 验证通过教师解答 | 筛选带来的改变 |
| D | 原始与通过解答混合 | 合成占比与覆盖 |

学生使用同一个 Base checkpoint、tokenizer、模板和训练 token 预算。
每题限制保留数，或者采用明确的 prompt 权重，避免易题过采样成为隐含处理差异。
保存 A/B/C/D 的长度分布；若回答长度变化，应采用一致截断规则并报告截断率。
评价使用固定官方 MATH test 和 GSM8K test，使用可信 grader/harness 的冻结配置。
测试集只在最终确认方案时运行，不因为某种过滤规则 test 分数更好就反复改阈值。

预先记录想验证的假设，例如“筛选能降低答案错误继承，但可能减少困难题覆盖”。
运行后用真实日志回答；若没有运行，提交实验方案与空白字段，不填估计分数。
对教师预算增加的实验，应同时比较同学生预算和同端到端成本两种视角。

## 7.11 失败模式与问题

- 接受率很高但学生退步：检查教师是否泄露答案、模板重复、训练/评价格式不一致。
- 长答案显著增加：检查判分器是否偏好长度，token 平均是否改变题目权重。
- 困难题几乎全部被删：检查每题接受率，不把筛选后容易题上的高准确率叫泛化提升。
- 生成记录缺失 revision：结果无法完整重建，应明确标注可复现限制。

思考：通过最终答案验证的错误推理链应否用于 SFT？需要什么额外证据？
若一个 teacher 对同题生成十条相同解法，通过数增长意味着增加了多少信息？
如何区分学生真的学会解题，和仅仅学会输出判分器喜欢的答案格式？
