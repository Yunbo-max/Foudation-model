# 16 · 前沿方向：把愿景拆成能测量的研究问题

“模型能够自己记忆、自己进化并完成长程任务”描述了值得探索的目标。
它没有指定记忆结构、更新算法、环境权限或独立验收方法。
完成基础课程后，下一步是把这些目标拆成可测量的问题，而不是把新术语叠在旧模型上。
本章连接多模态、世界模型、推理计算、开放训练与长程 Agent，并给出研究起点。

本教程是原创学习路径和基础实现，不是清华官方镜像，也没有执行完整 16 周训练计划。
阅读开放项目的发布结果，属于理解外部研究；复现结果必须由自己的运行记录支持。

## 16.1 多模态是信息接口变化

文本、图像、音频和视频具有不同采样方式、时间结构和噪声。
图像可分割为 patch 表示，音频可以使用连续特征或离散 token，视频还要保持帧间关系。
将表示投影到共享空间之后，仍要定义输入顺序、模态边界和输出目标。
统一 token 接口降低系统复杂度，却不自动保证所有模态的信息都被保留。

一种条件生成形式为：

$$
p_\theta(y\mid x_{\mathrm{text}},x_{\mathrm{image}},x_{\mathrm{audio}})
=\prod_t p_\theta(y_t\mid y_{<t},E_{\mathrm{text}},E_{\mathrm{image}},E_{\mathrm{audio}}).
$$

编码器表示 $E$ 可以预训练后冻结，也可联合训练；这改变参数成本和数据需求。
输出可能是文本、动作或另一模态，训练目标不能只按“有图片的聊天”理解。
字幕中出现的答案会形成捷径，因此评测应检查移除或打乱图像后是否仍能答对。

多模态 Agent 还需要观察与动作对齐。
截图中的对象要映射到可执行动作，音频指令要绑定说话人与时间，视频事件要绑定顺序。
识别能力强并不等于控制准确；观察错误与动作执行错误应分别诊断。

## 16.2 世界模型为何不同于生成好看的视频

世界模型尝试预测环境如何随动作变化。
一种学习目标是 $p_\phi(o_{t+1},r_t\mid h_t,a_t)$，在其中条件化动作是关键。
生成模型只预测“下一帧常见是什么”，可能无法回答“执行另一动作会发生什么”。
若训练数据没有覆盖干预动作，也不能从视觉逼真度推出反事实预测可靠。

模型式规划可以在学习模型中展开多条候选轨迹，选择预测回报高的动作：

$$
a_t^*=\arg\max_{a_{t:t+H-1}}\mathbb E_{p_\phi}
\left[\sum_{j=0}^{H-1}\gamma^j r_{t+j}\right].
$$

实际部署常只执行第一步，再观察环境并重新规划，降低长展开误差。
模型可能在真实数据覆盖之外给出乐观预测，使规划器利用模型漏洞。
需要估计不确定性、限制规划范围并用真实环境验证；预测奖励高不是最终任务成功。

[NVIDIA 的世界基础模型研究论文](https://arxiv.org/abs/2503.24320) 提供推理计算与世界模型结合的一个具体入口。
论文中的模型、数据和评估定义需要一起阅读；不能把某项视频预测结果直接推广到任意物理控制。
物理实验中的真实安全和硬件成本还会限制可探索动作，这与软件沙箱的重置条件不同。

## 16.3 三个前沿场景

**屏幕与声音协作。** 助手听到任务，同时观察页面。
研究问题是时间对齐是否帮助定位操作对象、在声音中断时能否正确恢复，以及是否能在固定预算内完成操作。
对照可以是文本转写加 DOM、截图加文本、联合模态输入；最终使用公开环境的实际状态验收。

**代码与长任务。** 修改可能跨多个模块，执行器需要持久状态、测试、恢复和依赖管理。
研究问题是失败记忆是否减少重复动作、异步工具是否节省墙钟时间，以及改进是否保持在未见 issue 上。
SWE-bench 与 Terminal-Bench 的固定公开版本可以提供任务证据，具体协议不能随方法自行简化。

**模拟环境规划。** Agent 先在预测模型中试走路径，再在环境中执行。
研究问题是预测误差如何随规划长度增长、真实观察多久校正一次，以及模型是否误导策略选择未覆盖动作。
MineRL 提供一个理解视觉控制与长期依赖的公开入口，但其安装、版本与任务定义必须固定。
没有执行真实控制实验时，模型生成的漂亮轨迹只能算候选预测。

## 16.4 推理时计算也是资源分配

同一个模型可以通过更多采样、检查、搜索或修正改变输出。
多试几次通常增加找到成功解的机会，但也增加成本，独立验证器会影响选择效果。
如果 verifier 与生成模型共享错误，多采样可能只让错误更一致。

设任务 $x$ 的计算预算分配为 $b(x)$，成功效用为 $U(x,b)$。
可将优化目标写为：

$$
\max_{b(\cdot)}\mathbb E_x[U(x,b(x))]
\quad\text{s.t.}\quad\mathbb E_x[C(x,b(x))]\leq B.
$$

困难任务可能更需要计算，也可能在当前模型能力下增加计算仍无效。
判断何时停止或升级工具，是一个需要保留集测量的决策问题。
固定预算下比较方法，比只展示“用了更多 token 后分数提高”更接近可检验结论。

研究时记录搜索分支数、每分支 token、验证次数和选中轨迹。
若只保存最后成功答案，会隐藏大量失败尝试和成本。
把推理时选择当成训练更新也会混淆：权重不变时，变化发生在采样与选择过程。

## 16.5 混合架构与稀疏计算

MoE 用路由器选择部分专家，减少每 token 激活的参数计算。
总参数量与激活参数量表达不同成本；路由通信、专家负载不均和推理批次大小也影响实际性能。
不能把参数量比值直接当作吞吐提升比例。

状态空间或混合 Mamba–Attention 架构改变长序列的信息流和缓存形态。
注意力擅长显式内容寻址，状态更新强调压缩；混合设计需要在任务与系统测量中判断取舍。
长上下文长度支持、有效利用长上下文能力与端到端长任务成功率是不同指标。
多 token 预测也需要结合训练目标、推理解码和验收结果解释，不能仅凭架构名称断言加速。

[Nemotron 官方开发仓库](https://github.com/NVIDIA-NeMo/Nemotron/blob/main/README.md) 包含不同模型的训练配方、部署指南及用例。
可阅读 [Nano 3](https://github.com/NVIDIA-NeMo/Nemotron/blob/main/docs/nemotron/nano3/README.md)、[Super 3](https://github.com/NVIDIA-NeMo/Nemotron/blob/main/docs/nemotron/super3/README.md) 和 [Lightning 3.5](https://github.com/NVIDIA-NeMo/Nemotron/blob/main/docs/nemotron/lightning35/README.md) 的当前入口。
这些入口在 2026-10-03 通过仓库树核验；版本将持续变化，研究需锁定 commit。
官方 README 明确某些公开配方仅使用公开数据子集，不能默认与技术报告完整训练条件相同。

## 16.6 开放训练不是一个仓库的能力

完整链路包含原始数据、清洗去重、tokenizer、训练循环、分布式系统、检查点、后训练和评测。
开源代码不等于全部数据公开；开放权重不等于训练过程可复现；公开配方不等于拥有同等算力即可逐项复刻结果。
阅读模型报告时列出哪些部分能下载、哪些能执行、哪些仅提供描述。

DCLM 更适合学习数据筛选与固定训练预算下的比较。
The Pile 更适合学习多来源语料构建与数据谱系，组件许可仍需单独审查。
OLMo 原库保存早期训练实现，当前 README 指向 Olmo-core；后者提供更新的训练模块和官方脚本。
open-instruct 聚焦后训练与评估；NeMo 系列进一步拆分训练后端、RL 与数据工具。
它们承担不同角色，详细文件入口见 [开放训练源码导读](../references/open-training.md)。

## 16.7 长程 Agent 还缺哪些系统条件

真正长程任务需要持久状态、环境恢复、工具超时、权限边界、任务级回报和故障诊断。
大规模训练还需要采样集群、策略版本管理、可重置环境、轨迹存储与独立验收。
工具服务失败会改变观测分布，策略升级会改变访问状态，网页版本变化会改变任务条件。
因此长程 Agent 的进展应同时测能力、稳定性和成本。

[agent.py](../src/fm_tutorial/agent.py) 的有界 callable 循环是理解这些边界的起点。
它没有实现并发环境、完整 on-policy 训练、真正持久记忆或可强制中断的工具进程。
从接口练习到公开基准评测，再到训练收益，每一步都需要新的实际证据。
本仓库不把计划文档、教学测试或第三方发布分数写成已经完成的长程训练。

## 16.8 用一张研究卡开始

研究卡至少写明：问题、机制假设、任务协议、对照、预算、评分器、数据隔离和可能推翻假设的结果。
例如“带来源的失败记忆是否降低网页流程重复错误”，比“实现自我进化 Agent”更容易检验。
固定 BrowserGym/WebArena 版本，比较无记忆与单一记忆设计，保留模型和 token 预算。
按失败类型报告结果；若只在同一任务重试有效，而新实例无收益，结论应限制在重试辅助。

代码研究可选择 SWE-bench 的官方训练和评测划分，先复现固定策略基线。
数据研究可用 DCLM 的指定规模和协议比较过滤方法，记录真实训练而不是导入合成 scaling 曲线。
系统研究可测实际硬件的吞吐和内存，但必须同时验证数值与任务表现。
没有资源运行时，提交可执行配置和待验证假设，结果栏明确“未测”。

## 16.9 新闻、课程与科学证据的角色

课程地图帮助组织学习顺序，教材帮助建立概念，个人仓库帮助对照实现，新闻说明行业讨论背景。
算法事实与能力结果应回到论文、官方代码、数据卡和实际日志。
用户提供的四篇报道都列入 [来源导读](../references/open-training.md)，其中“自我进化”的报道只作为愿景背景。
报道中的宣言不能替代环境验证、训练日志和未见任务实验。
