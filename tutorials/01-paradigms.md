# 01　学习范式：从给答案，到预测文本，再到行动反馈

> 前置：[00 预备知识](00-prerequisites.md)；后续：[02 架构](02-architecture.md)。

## 1.1 同一个需求，三种建模方式

假设我们需要帮助用户理解一篇科研文章。
早期系统可能先手写关键词与句法规则，再把句子分类为“问题、方法、结果”。
监督学习系统从标注样本学分类器；预训练语言模型先从大量文本学习语言规律，再接受少量任务适配。
Agent 系统则可能读论文、检索对照研究、运行代码，在新的观察出现后决定下一步。
区别不只是网络更大，而是哪些信息可以成为学习信号，以及系统如何接收反馈。

唐杰课程公开地图以“范式转移”和 learning signal ladder 串联主题。
以下是为学习建立的解释框架，不把复杂历史硬切成某个统一年份，也不声称所有领域同时转型。
统计学习、深度表示、生成预训练与交互反馈常常同时存在。
一个真实系统也可能用分类器做质量过滤，用语言模型产生候选，用程序验证器判定答案。

| 方式 | 样本提供什么 | 模型要学什么 | 主要瓶颈 |
| --- | --- | --- | --- |
| 任务监督 | 输入与人工标签 | 指定任务上的映射 | 标签成本、分布变化 |
| 表示学习 | 原始对象与结构性目标 | 可迁移的内部表示 | 目标是否保留有用信息 |
| 自回归预训练 | 文本本身 | 条件分布与续写规律 | 数据、计算、目标错位 |
| 偏好学习 | 两个回答的比较 | 用户或标注者偏好 | 偏好偏差与覆盖范围 |
| 可验证强化学习 | 回答与外部判定 | 提高通过验证的概率 | 验证器漏洞、探索成本 |
| 环境交互 | 动作、观察、延迟回报 | 长程决策策略 | 信用分配与状态变化 |

## 1.2 监督学习：为什么标签定义了问题

给定 $n$ 个样本 $\{(x_i,y_i)\}_{i=1}^n$，经验风险是：

$$
\hat R(\theta)=\frac1n\sum_{i=1}^n\ell(f_\theta(x_i),y_i).
$$

$x_i$ 可以是一段文本，$y_i$ 可以是类别、数值或序列，$f_\theta$ 输出必须与损失定义匹配。
以三分类为例，logits 形状为 `[B,3]`，标签形状为 `[B]`。
标签告诉模型哪些变化需要保留：情感分类需要关注立场，而作者分类可能关注措辞与文体。
模型不是从输入中“自动发现所有正确目标”，它在给定损失下调整参数。

泛化风险 $R(\theta)=\mathbb E_{(x,y)\sim\mathcal D}\ell(f_\theta(x),y)$ 通常无法完整计算。
独立验证集只是它在选定分布上的估计。
训练集准确率高，不能证明新时期、新语言或新领域上仍然准确。
当项目不断用验证集调参，验证集也逐渐参与决策；最后还需要独立测试集。

## 1.3 表示学习：把特征设计的一部分交给模型

把文本表示为人工关键词计数时，词序与跨句联系可能丢失。
可学习嵌入让任务梯度调整每个符号的向量，深层网络继续组合局部与全局信息。
“分布式表示”意味着语义可能由多个维度共同编码，而不是一维对应一个固定概念。
单个神经元的可视化只能提供局部线索，不能替代整个模型行为的评估。

如果目标是从上下文区分正确词与错误词，即使不提供情感标签，也能得到有用的语言表示。
但不同自监督任务学到的信息不同：遮盖恢复可以使用双向上下文，自回归预测只允许使用前缀。
选择训练目标会改变允许的信息流，也会影响模型的推理用法。
本仓库选择 decoder-only 自回归目标，因此 [model.py](../src/fm_tutorial/model.py) 的因果遮罩是目标定义的一部分。

## 1.4 从字符串到 token：基础设施也会改变学习问题

计算机保存 Unicode 文本时常用 UTF-8；一个汉字通常包含多个字节。
本项目 [tokenizer.py](../src/fm_tutorial/tokenizer.py) 从 256 个字节符号出发，另设 EOS=256、PAD=257，合并 token 从 258 起编号。
这样任意 UTF-8 文本都能由字节表示；未见词不必依赖一个统一的未知词 ID。
字节可表示不等于模型已学会该语言，覆盖性和能力是两个概念。

BPE 的核心步骤是反复把频繁相邻符号合成新符号：

1. 将训练文本变成初始字节序列，并统计相邻 pair。
2. 选择一个最频繁 pair，按固定规则处理并列情况。
3. 给它分配新 ID，再在训练序列中用新符号替换该 pair。
4. 更新统计，直到预算耗尽或没有可合并 pair。
5. 编码新文本时按训练得到的合并优先级执行，而非重新统计频率。

假设训练文本常出现 `foundation`，BPE 可能逐步把多个字节合为更长片段。
这只是机制示意，不是本仓库已训练词表的观测；实际合并必须在真实语料上检查。
token 不保证与汉字、英文单词、语素或概念一一对应。
词表更大可能减少序列长度，但增大嵌入与输出层，也可能让低频 token 很难学。
因此 tokenizer 的好坏要结合压缩率、训练成本、语言覆盖与实际验证损失分析。

词表训练只能使用训练 split，不能借验证文本选择合并。
Tokenizer 保存文件应携带完整 ID 与合并信息；只保留“词表字符串列表”可能无法恢复编码次序。
UTF-8 roundtrip 测试是工程正确性检查；几十条测试字符串不是训练 benchmark。

## 1.5 自回归目标：每段文本天然产生很多监督位置

token 序列 $x=(x_1,\ldots,x_T)$ 的概率按链式法则展开：

$$
p_\theta(x)=\prod_{t=1}^{T}p_\theta(x_t\mid x_{<t}),\qquad
\log p_\theta(x)=\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{<t}).
$$

这是概率分解恒等式；它本身不规定网络必须是 Transformer。
下一 token 负对数似然目标为：

$$
L_{\mathrm{NTP}}=-\frac1M\sum_{b,t}m_{b,t}\log p_\theta(x_{b,t+1}\mid x_{b,\le t}),
\quad M=\sum_{b,t}m_{b,t}.
$$

logits 为 `[B,T,V]`，mask 为 `[B,T-1]`，$m_{b,t}=1$ 表示一个有效监督位置。
分母 $M$ 是有效目标 token 数，不能机械地用 $BT$ 包含 PAD。
训练采用 teacher forcing：每个位置输入真实前缀，所以所有位置可并行计算。
生成时未知后续 token，必须按当前分布采样或选取一个 token，再将它加入前缀。
这就是“训练并行、生成串行”常见差异的根源。

最大似然使模型拟合数据分布。
若数据包含错误、偏见与重复，它们也可能成为可预测规律。
语言规律可以支撑迁移，但较低交叉熵不自动保证数学正确、引用可靠或行动安全。
后续章节引入偏好与 verifier，正是因为部署目标通常不是纯文本复现。

## 1.6 场景一：续写百科与回答问题是两个接口

给模型一段 WikiText 文章，让它续写，是直接使用预训练分布。
给它“请用三点总结”这样的指令，需要它识别指令格式并输出相应行为。
如果预训练语料很少包含这种交互，单靠生成概率未必能稳定遵从。
SFT 把指令和回答配成训练样本，通常只在回答区间计算损失，详见后续 SFT 章节。

同一段知识可能既用于续写又用于问答，但评价方法不同。
续写看固定真实文本的 token NLL；问答应看具体题目的答案正确性、引用与格式。
如果问答答案早已出现在训练文本中，模型答对可能反映记忆，不足以证明新问题上的推理。
因此应记录评估题与训练数据的重合检查，而非只展示几个满意的截图。

## 1.7 In-context learning：文本中的例子怎样起作用

在 prompt 中放几个输入输出例子，可以改变后续条件分布：

$$
p_\theta(y\mid x,\underbrace{(x^{(1)},y^{(1)}),\ldots}_{\text{上下文示例}}).
$$

普通推理中参数 $\theta$ 不更新；示例经注意力等计算影响隐藏状态。
这和 fine-tuning 的梯度更新不同，也和外部数据库的持久记忆不同。
上下文窗口有限，示例顺序、长度与标签格式都可能改变结果。
一个模型能根据例子继续序列，不代表它对示例中隐含规则做了唯一正确的归纳。

考虑把任务从“词语→首字母”换成“词语→长度”。
少量示例可能同时兼容多种规则，下一条回答暴露模型的归纳偏好。
这类手工短例适合解释条件化，不能用来报告普适学习能力。
实际比较应在公开任务集上固定示例池、题序、输出解析与 seed。

## 1.8 场景二：代码任务为什么适合外部反馈

一个代码回答看起来很像正确解法，但语言形式无法确认程序在边界输入上是否成立。
单元测试、编译器和静态检查器可以提供部分外部证据。
若只有“通过公开样例”奖励，模型可能过拟合样例或利用测试缺陷。
更好的设置包括独立隐藏测试、运行资源限制、完整失败日志与明确任务边界。

将策略的输出记为动作 $a\sim\pi_\theta(\cdot\mid s)$，奖励为 $r(s,a)$。
训练目标可写成 $J(\theta)=\mathbb E_{a\sim\pi_\theta}[r(s,a)]$。
文本概率提供可微策略，奖励提供任务反馈；两者不是同一个数。
由于动作是离散采样，不能直接把测试结果当作交叉熵标签反传，需策略梯度或其他学习机制。
第 10 章将进一步讨论 RLVR 与训练不稳定性。

## 1.9 场景三：反馈延迟后，问题变成决策过程

假设模型在仓库里修 bug，要先定位文件、读测试、修改代码，再运行验证。
前一次动作会改变后续观察，最后成功由多个动作共同决定。
状态 $s_t$、动作 $a_t$、转移 $P(s_{t+1}\mid s_t,a_t)$ 和奖励 $r_t$ 组成交互问题。
折扣回报 $G_t=\sum_{k\ge0}\gamma^kr_{t+k}$ 中 $\gamma\in[0,1]$ 调节远期收益权重。

仅训练“最后答案写得好”不一定教会模型正确地选择中间工具。
只奖励每步输出顺畅，也可能鼓励没有进展的长轨迹。
环境必须保留动作与观察，终止条件必须明确，成功判定应来自独立状态检查。
本仓库 [agent.py](../src/fm_tutorial/agent.py) 是有界、可审计的 harness 基础，不是已经训练好的长程 Agent。

## 1.10 把学习信号按证据强度理解

| 信号 | 直接观察 | 不能直接推出 |
| --- | --- | --- |
| next-token | 文本与候选分布是否一致 | 回答事实为真 |
| 偏好 | 某比较者更喜欢一个回答 | 所有用户都喜欢、答案正确 |
| verifier | 在已定义规则下通过 | 未覆盖情况均正确 |
| 环境成功 | 任务终态满足检查 | 中间步骤没有副作用 |
| self-judge | 模型对自己的判断 | 独立真实性证据 |

信号越可规模化，覆盖面越可能扩大，同时偏差也能被规模化。
模型自己给出的高分不能代替独立测试；“让人退出闭环”仍需要治理与审计设计。
课程后半程的主题可以看成不断扩大可反馈问题的范围，同时管理信号误差。

## 1.11 真实实验：目标、表示与 token 预算一起报告

在固定 WikiText 训练/验证切分上训练三种 BPE 词表预算，例如 512、1024、2048。
这些是待运行的实验设置，不是优劣排名；真实训练词表可能达不到预算。
记录实际词表、每文档 token 数分布、字节/token、编码耗时与未知字节覆盖。
若分别训练语言模型，保持宽度、层数、有效 token 或计算预算，并明确哪些没有保持。
词表改变会同时改变参数数、序列长度和任务分解，不能把结果全归因于“语义更好”。

跨 tokenizer 比较可补充 bits-per-byte：

$$
\mathrm{BPB}=\frac{\sum_t-\log p(x_t)}{\log 2\cdot \#\text{原始 UTF-8 字节}}.
$$

该式需要每个真实文本目标计数一致，边界 token 是否计入需声明。
它改善单位可比性，仍不能消除文本预处理和 context 条件差异。
不要把不同训练预算下的 BPB 当成纯粹 tokenizer 实验。
详细交付规范见 [作业一](../assignments/01-foundations.md)。

## 1.12 检查理解

1. 为什么 next-token 目标能产生很多监督位置，却仍不能自动提供事实标签？
2. 手算一个三候选分布中正确 token 的交叉熵，并解释提高错误候选 logit 的影响。
3. tokenizer 词表扩大两倍时，为什么不能直接宣称计算节省两倍？
4. in-context learning、参数微调、检索记忆分别改变系统的哪部分？
5. 为代码修复任务设计一个会被钻空子的奖励，再改进它的检查边界。
